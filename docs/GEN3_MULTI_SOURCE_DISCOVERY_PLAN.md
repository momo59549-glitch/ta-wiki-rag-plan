# Gen3 多源策略发现与收益门槛实施计划

状态：已批准架构，等待分阶段实现
制定日期：2026-08-12
适用仓库：`ta-wiki-rag-plan`

## 1. 目标与边界

Gen3 的目标不是保证未来收益，而是建立一条可审计的自动发现漏斗：从量价、财务单因子、公司公告事件和时效新闻中产生有限数量的候选；先以完整组合的净收益、超额收益和风险门槛进行历史淘汰；只有合格候选才允许进入前瞻验证和最终锁箱。

本计划明确不作以下承诺：

- 不承诺任何策略未来必然达到目标年化收益。
- 不把单笔平均收益、胜率或事件后平均涨幅冒充组合年化收益。
- 不把已经查看或参与过选择的数据重新命名为“锁箱”。
- 不允许在看到结果后降低收益门槛、替换基准、修改成本或挑选有利年份。
- 不允许通过重命名、等价参数或更换策略描述绕过全局试验预算。

## 2. 与 Gen2 的关系

- 当前 Gen2 `r3` 保留为 `never-run` 审计记录，不删除、不覆盖、不执行。
- Gen2 已经登记的候选和历史试验继续计入全局试验清单。
- Gen3 使用新的协议、数据清单、候选空间、账本和验证目录；不得修改 Gen2 的 write-once 产物。
- 截至本计划制定时，全局唯一逻辑预算为 256，已使用 214，剩余 42。

## 3. 冻结的经济与风险门槛

所有门槛必须在第一次 Gen3 结果产生前写入不可变研究协议。默认门槛如下：

| 指标 | 历史资格赛最低门槛 | 说明 |
|---|---:|---|
| 扣除基础成本后的组合 CAGR | 12% | 使用完整资金曲线，包含空仓现金 |
| 相对匹配基准的年化超额 | 5 个百分点 | 基准按可投资股票池预先冻结 |
| 2 倍成本压力下组合 CAGR | 8% | 手续费和滑点同时加倍 |
| 最大回撤 | 不高于 20% | 以日终组合净值计算 |
| Calmar | 不低于 0.8 | CAGR / 最大回撤绝对值 |
| 盈利时间折占比 | 不低于 70% | 使用预登记的 walk-forward 时间折 |
| 单一时间折利润贡献 | 不高于总正利润的 50% | 防止结果由单一行情阶段驱动 |
| 数据与可交易性 | 100% 通过 | PIT、停牌、涨跌停、ST、新股、退市和复权检查 |

补充规则：

- 不足一年的前瞻区间不直接展示为“已实现年化”。晋级时使用同期累计收益门槛 `(1 + 12%)^(实际天数/365.2425) - 1`，同时报告未年化累计收益。
- 绝对收益达标但未跑赢冻结基准的候选不得晋级。
- 经济门槛先于统计显著性；年化只有 5% 的规则不能因 p 值漂亮而晋级。
- 所有候选与所有持有期组成一个完整多重检验族，不得只校正最终展示的赢家。
- 如无候选达标，正式结论必须是“本轮无合格策略”，不得强行保留候选。

## 4. 数据范围与 PIT 规范

### 4.1 数据赛道

1. 行情与可交易状态
   - OHLCV、复权因子、交易日历、历史指数成分。
   - ST/退市整理、停牌、上市天数、涨跌停和次日是否可成交。

2. 财务单因子
   - 价值、质量、盈利能力、成长、低波动、流动性、规模和股东回报。
   - 财报按实际首次披露时间生效，不按报告期结束日提前生效。

3. 公司公告事件
   - 业绩预告及修正、回购、增减持、分红、限售解禁、重大合同、诉讼、处罚等。
   - 优先使用巨潮资讯、上交所和深交所等官方披露源。

4. 时效新闻
   - 情绪、方向、新颖度、意外性、传播持续性、公司/行业实体映射。
   - 新闻源必须具有可验证的历史发布时间和合法可复现的获取方式；没有可靠历史时间戳的语料不得用于历史回测。

### 4.2 统一 PIT 字段

每条非行情信息至少包含：

- `source`
- `source_record_id`
- `published_at`
- `available_at`
- `effective_session`
- `revision_id`
- `content_hash`
- `ingested_at`
- `symbol_mapping_version`

交易规则：收盘前已公开且数据源当时可获得的信息，最早只能在协议允许的下一成交点使用；收盘后发布的信息最早从下一交易日使用。修订公告必须形成新版本，不能覆盖旧版本。

### 4.3 存储

- 不引入 SQL 作为前置要求。
- 表格数据采用压缩 Parquet，协议、清单、哈希和小型事件元数据采用 canonical JSON。
- 原始快照 write-once；衍生特征记录输入清单哈希、代码快照、构建时间和特征版本。
- 大型可重建缓存默认不提交 Git；协议、清单、哈希、少量固定 fixture 和最终摘要允许提交。

## 5. 候选空间与试验预算

42 个剩余唯一逻辑预算分配如下：

| 赛道 | 新候选上限 | 示例范围 |
|---|---:|---|
| 量价/技术 | 8 | 残差反转、趋势回调、突破、波动收缩、相对强弱 |
| 财务单因子 | 12 | 价值、质量、成长、盈利、低波动、流动性、规模、股东回报 |
| 公告事件 | 10 | 预告、回购、增减持、分红、解禁、合同、处罚和诉讼 |
| 时效新闻 | 6 | 情绪、意外性、新颖度、热度持续性及行业扩散 |
| 保留预算 | 6 | 协议级错误修复或预登记对照；不得用于结果导向调参 |

候选生成约束：

- 一条候选最多由一个主信号、一个环境过滤器和一个预先定义的组合构建规则组成。
- 参数只能来自协议白名单；不运行连续黑箱优化、遗传搜索或无限网格搜索。
- 同一经济逻辑的参数变体分别计入预算；语义等价逻辑按一个唯一逻辑去重，但不得用等价改写规避历史失败记录。
- 每个新闻分类器、嵌入模型、提示词或阈值版本均属于候选身份的一部分；更换后必须计入新试验。
- 保留零信号、简单等权和冻结指数作为对照，它们不参与赢家粉饰。

## 6. 历史资格赛

### 6.1 时间角色

- 2015-01-01 至 2020-12-31：发现、训练和有限参数选择。
- 2021-01-01 至 2021-12-31：历史资格窗口；因为该数据已经存在且可能被查看，只能标记为开发证据，不得称为锁箱。
- 2022-01-01 至 2026-08-31：跨状态稳健性和压力检查；同样属于已见开发数据。
- 使用锚定 walk-forward，并在特征窗口、标签窗口和持有期之间执行 purge/embargo。

### 6.2 统一执行语义

- 信号只使用当时可获得的数据。
- 日线信号默认 T 日可用信息、T+1 开盘成交。
- 财务、公告和新闻事件以 `effective_session` 决定首个合法成交点。
- 同时模拟停牌、涨跌停、无法成交、延迟退出和未解决持仓。
- 组合采用冻结的资金、持仓上限、等权或预登记权重规则；不得把重叠事件当作无限资金的独立交易。
- 基础成本、2 倍成本、基准、持有期和退出规则全部写入协议。

### 6.3 统计与稳健性

- 以日度组合收益为主要统计对象，不以高度相关的逐股票事件行虚增样本量。
- 使用适当的 HAC/区块自助法处理时序相关。
- 对全部候选 × 全部冻结持有期应用 BH-FDR；必要时增加 SPA/PBO 作为研究级诊断。
- 报告 CAGR、累计收益、年化超额、最大回撤、Calmar、换手、成交失败率、容量代理、年份/市场状态分解和 2 倍成本结果。
- 所有失败和被淘汰候选必须进入不可变账本。

## 7. 前瞻验证与最终锁箱

### 7.1 前瞻验证

- 计划窗口：2026-09-01 至 2027-02-28。
- 历史资格赛最多冻结 8 个互补候选；不要求凑满 8 个。
- 所有候选并行运行，禁止一个失败后再临时设计替代者并共享同一检验口径。
- 前 3 个月只允许按预登记无效/风险规则提前淘汰，不允许宣布胜出。
- 6 个月结束后，同时检查同期累计收益目标、基准超额、成本压力、回撤和数据完整性。

### 7.2 最终锁箱

- 按预登记排序规则最多选择 1 个前瞻合格候选。
- 建议起始时间不早于 2027-03-01。
- 最低持续 3 个月且不少于 60 个有效交易日；事件策略还必须满足协议规定的最小独立事件数。
- 样本不足时只能延长，不能降低门槛或补读锁箱后修改规则。
- 锁箱只作最终确认；锁箱失败意味着候选失败，不回头重选同批次第二名。

## 8. 实现阶段与验收条件

主板范围约束的本地 Phase 1 补充见
[GEN3_MAINBOARD_UNIVERSE.md](GEN3_MAINBOARD_UNIVERSE.md)：仅沪深主板，不含创业板、
科创板、北交所或其他板块。该本地内容归属已完成 3,400 成员、17 个补充及 0 missing，
但仍不是 PIT 或回测授权；下一阻断是每日可交易性（停牌/涨跌停/可成交）和
benchmark/index constituent 的 PIT 证据。

可交易性证据充分性草案见 [GEN3_TRADABILITY.md](GEN3_TRADABILITY.md)；在权威日历、
停牌、涨跌停与 PIT ST 历史到位前，主板 universe 不得用于回测。

### Phase 0：现状盘点与协议骨架

交付物：

- Gen3 数据可用性矩阵。
- 当前本地行情、财务、公告、新闻、指数成分和可交易状态覆盖报告。
- 现有 214 个历史逻辑与剩余预算的只读复验。
- Gen2 r3 `never-run` 状态复验。
- Gen3 policy/contract schema 草案和目录设计。

验收：只读盘点不得触发正式试验、不得登记候选、不得读取任何未来锁箱结果、不得下载大量外部数据。

### Phase 1：PIT 数据与特征注册表

交付物：

- 统一 source manifest、revision manifest、PIT event schema。
- 财务、公告、新闻和行情 provider 接口。
- `effective_session` 计算器、修订处理、实体映射版本和内容哈希。
- 小型合成 fixture 与防穿越测试。

验收：覆盖收盘前/后、周末节假日、修订公告、缺失时间戳、重复记录、代码映射变化和不可交易次日。

### Phase 2：候选 DSL 与四赛道生成器

交付物：

- 四赛道候选 grammar、白名单和 canonical semantic identity。
- 42 次预算账本及写前复验。
- dry-run 只展示候选身份和所需数据，不计算收益。

验收：语义等价去重、已测逻辑拒绝、预算超限 fail-closed、新闻模型版本绑定。

### Phase 3：统一组合回测与历史资格赛

交付物：

- PIT 事件到订单、成交、持仓、现金和净值的统一执行器。
- walk-forward、purge/embargo、基准和成本压力评估。
- 完整候选族的统计校正、排名与淘汰报告。

验收：构造的穿越数据、未来修订、不可成交订单、资金重复使用、赢家选择后换基准均必须被测试拒绝。

### Phase 4：正式冻结与前瞻运行

交付物：

- 最多 8 个历史合格候选的不可变协议。
- 数据版本、代码快照、候选身份、基准、收益门槛和未来窗口绑定。
- 可恢复的日增量 runner、checkpoint、shard 和审计摘要。

验收：主代理在正式写入前完成代码、测试、协议、候选预算和数据清单审查；未经明确批准不得正式预登记或启动未来运行。

## 9. 子代理与审核职责

实现子代理使用 `gpt-5.6-terra`，按 Phase 0 → Phase 4 顺序工作。每一阶段完成后必须停止并报告：

- 修改文件。
- 关键架构决定。
- 测试及结果。
- 尚未覆盖的风险。
- 是否写入 `data/`、是否登记试验、是否读取锁箱。

主代理职责：

- 冻结大方向、经济门槛、阶段边界和不可变协议。
- 审查代码、数据泄漏、统计口径、试验预算及正式产物。
- 只在上一阶段满足验收条件后授权下一阶段。
- 正式试验、外部大规模下载、锁箱读取和 Git 提交/推送均单独确认权限。

## 10. 首个实施指令

子代理当前只执行 Phase 0：现状盘点与协议骨架。不得开始 Phase 1，不得运行正式回测，不得登记新的 36 个候选，不得创建正式 Gen3 协议，不得读取未来锁箱，不得下载大型数据。Phase 0 结果经主代理审核后再决定 Phase 1 的精确接口。
