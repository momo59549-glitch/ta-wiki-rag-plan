# 执行摘要

## 当前系统最核心的能力是什么？

将日线规则研究做成可追溯的文件型闭环：冻结数据/代码/协议，T 收盘→T+1 开盘生成 Observation/Outcome，做样本外统计、FDR、成本压力、Case/审批/知识证据审计。其最成熟价值是**证伪和留档**，不是提供可交易信号。

## 最薄弱的 5 个地方是什么？

1. 没有通过最终锁箱且可发布的策略；已有正式候选全淘汰。
2. 数据 PIT 不完整：财务/公告时间、供应商修订、正式历史成分、停复牌和涨跌停未闭环。
3. 回测成本/执行仍是日线近似，缺税费、最低佣金、整手、容量、冲击、封板/停牌订单可成交性。
4. 无账户、订单、组合风控和实盘/纸交易闭环；无法直接转为小资金交易系统。
5. 文件型运行时/大体量工件已接近需要数据生命周期、对象存储和事务数据库治理的阶段。

## 有没有明显未来函数或数据泄漏风险？

主信号/成交边界设计较好：T 收盘信号移至 T+1 open，开盘成交检查不看当天收盘量，且有锁箱/PIT universe/强快照门禁。明显残余风险在**数据层**：复权与供应商历史修订没有 availability lineage；ST/停复牌/涨跌停是近似；历史 OOS 已被查看，不能重新称为未见测试集。

## 有没有明显过拟合风险？

有。虽有有限 grammar、预注册、FDR、成本压力、regime、多 horizon、Jaccard 去重和未来 lockbox，但 2022–2026 已被多轮搜索/比较；人的规则空间设计和失败后扩展 grammar 仍有研究者自由度。没有 bootstrap/Reality Check/SPA/Deflated Sharpe，锁箱也未执行。

## AI 目前是“问答助手”还是“自主研究员”？

是**受证据约束的问答助手 + 确定性研究工作流**，不是自主研究员。LLM 只能根据已审校知识卡答题；不能制定实验、调用回测、读取结果后自我迭代、审批或发布。

## 哪些模块已经成熟值得保留？

- Rule DSL/语义 hash、T+1 Observation/Outcome 边界。
- 强数据快照、代码/协议绑定、分片 commit 与可恢复 artifact。
- 文件 Case 状态机、RBAC、审批、Outbox/Worker 控制面。
- 规则搜索的 FDR/成本压力/Jaccard/负结果记录。
- PDF/EPUB 证据—知识卡—BM25—受限 LLM Answer 链路。

## 哪些模块可能需要重构？

- 统一回测内核：把事件 Outcome、vectorbt、Backtrader、候选 ledger 收敛为同一订单/成本/执行契约。
- 数据层：引入版本化、可得时间/PIT、企业行为、财务/公告、正式可交易性数据模型。
- 存储层：当多人/容量需求确认后，将文件控制面和大工件升级为关系数据库 + 对象存储；不要把目标态误认为现状。
- Qlib/ML 层：要么与研究协议、数据快照、回测契约深度整合，要么明确剥离为独立实验区。

## 如果只允许继续开发 3 个功能，你建议是什么？

1. **PIT 数据与交易性事实层**：版本化股票池、退市/ST、停复牌、每日涨跌停、财务发布日期/公告时间；每个字段有 source/available_at/revision。
2. **统一的小资金订单级回测/纸交易引擎**：Top-N/现金/整手/佣金最低收费/印花税/过户费/滑点/停牌涨跌停/退出延迟/持仓风控，共用同一执行契约。
3. **真正未来锁箱的预注册验证与研究注册表**：冻结策略族/预算后只执行一次新数据 OOS，并把结果、失败、代码/数据版本和人工裁决写入不可变 registry。
